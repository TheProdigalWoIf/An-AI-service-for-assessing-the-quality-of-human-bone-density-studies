## О проекте

Сервис решает задачу автоматической оценки качества укладки DXA-снимков поясничного
отдела позвоночника и проксимального отдела бедра. Для каждого снимка определяются:

- анатомическая область (`lumbar_spine` / `proximal_femur`);
- сторона бедра (`right` / `left`) — самостоятельная голова модели, обученная на
  экспертной разметке (по координате объекта на изображении сторона не определяется);
- итоговое решение: **хороший (0) / плохой (1)** с перечнем нарушенных критериев;
- статус решения (`ok` / `needs_review`) — когда уверенности недостаточно.

Данные разбиты на два набора: `Results` — 80 обучающих исследований (207 снимков,
в веб-интерфейсе не показываются) и `Исследования_тест` — 20 тестовых исследований
(44 снимка), на которых модель **не** обучалась. Проверка модели — только на внешнем
тестовом наборе.

## Логика модели (схема экспертизы)

```
СНИМОК → анатомическая область (lumbar_spine | proximal_femur)
        ├─ ПОЗВОНОЧНИК: укладка, ось, артефакты          (3 критерия)
        └─ БЕДРО: сторона (right|left, экспертная разметка)
                   → ротация/позиционирование, ROI        (2 критерия)
        → ИТОГОВОЕ РЕШЕНИЕ: хороший (0) / плохой (1)
        → ПРИЧИНЫ: какие именно критерии нарушены
```

- Плохой снимок всегда получает конкретную причину: если ни один критерий не превысил
  порог, берётся самый вероятный применимый критерий, а решение помечается
  `decision_status=needs_review`.
- Критерий «ось позвоночника» решается не сетью, а геометрией: наклоном средней линии
  самой колонки позвоночника (норма по методичке ≤5°). Наклон всего кадра и наклон
  колонки — разные вещи: при сколиозе колонка изогнута при почти вертикальной средней
  оси. Голова оси сети на 9 размеченных примерах не выучилась (AUC ≈ 0.5), поэтому при
  наклоне колонки ≤5° «отклонение оси» невозможно, при >5° — обязательно; расхождение
  геометрии и сети уводит решение в `needs_review`. Угол изгиба (`segment_angle_degrees`)
  вычисляется и передаётся в разметку, но решающего права пока не имеет (~30% ложных
  срабатываний; после переразметки по конвенции «двух линий» будет откалиброван).
- Резервные правила `qc.py` (когда чекпойнта нет) сторону бедра не выдумывают:
  `needs_review`.

## Архитектура

Приложение — монолитный FastAPI-сервис: REST API и статический веб-интерфейс из одного
процесса, модель загружается в память при старте.

```
                    ┌──────────────────────────────────────────────┐
DICOM/JPEG/PNG/WebP │  Веб-интерфейс (static/: HTML+JS+CSS)        │
  или Исследования_ │        │  HTTP (JSON, multipart)             │
       тест         │        ▼                                     │
                    │  FastAPI (api.py, 12 эндпоинтов)             │
                    │        │                                     │
                    │        ▼                                     │
                    │  inference.py — пайплайн экспертизы:         │
                    │   dicom.py → ml.py (ResNet18, 8 голов)       │
                    │            + geometry.py (ось позвоночника)  │
                    │            + qc.py (резервные правила)       │
                    │        │                                     │
                    │        ▼                                     │
                    │  models.QCResult → JSON / CSV / предпросмотр │
                    │  repository.py — чтение/запись labels.csv    │
                    └──────────────────────────────────────────────┘
```

Модули пакета `dxa_qc` (`src/dxa_qc/`):

| Модуль | Ответственность |
|---|---|
| `main.py` | Фабрика FastAPI-приложения, статика, отключение кэша UI |
| `api.py` | Все REST-эндпоинты, загрузка файлов, экспорт CSV |
| `config.py` | `Settings` — пути к данным/разметке/моделям (переопределяются переменными окружения) |
| `dicom.py` | Чтение DICOM, нормализация пикселей |
| `ml.py` | Мультитаск ResNet18: область, сторона, бинарное качество, 5 критериев |
| `inference.py` | Пайплайн экспертизы (точка входа для API): снимок → область → сторона → критерии → решение |
| `geometry.py` | Геометрическая ось позвоночника (наклон колонки, угол изгиба) |
| `qc.py` | Резервные правила контроля качества без чекпойнта |
| `calibration.py` | Калибровочная модель качества (отдельный артефакт по методичке) |
| `repository.py` | Потокобезопасное чтение/запись `labels.csv` |
| `models.py` | Dataclass-модели результатов (`QCResult`, `LabelRecord`) |
| `schemas.py` | Pydantic-схемы запросов |
| `metrics.py` | Метрики (confusion matrix и др.) |
| `static/` | Веб-интерфейс (HTML + JS + CSS, без сборки) |

Обучение и оценка вынесены в `scripts/` (см. [Обучение и оценка](#обучение-и-оценка)) —
сервис работает с уже обученными весами из `models/`.

## Развёртывание

### Системные требования

Windows 10/11 x64, macOS или Linux; Python 3.12+ x64. Минимальная конфигурация:
2 CPU, 2 ГБ RAM, 1 ГБ на диске; GPU не требуется. Типичное время обработки одного
изображения — меньше секунды.

### Windows

1. Запустить `setup_windows.bat` и дождаться установки зависимостей (создаётся
   окружение `.venv`; если `annotations/labels.csv` отсутствует — создаются
   первичные заготовки разметки).
2. Запустить `run_windows.bat`.
3. Открыть `http://localhost:1639`.

### macOS / Linux

Вариант 1 — двойным щелчком по `run_mac.command` (macOS): при первом запуске он сам
создаст окружение, установит зависимости и откроет сервис. Если Terminal сообщает,
что файл не выполняется, один раз выполните из папки проекта
`chmod +x run_mac.command scripts/*.sh` либо запускайте через `sh run_mac.command`.

Вариант 2 — в терминале из папки проекта:

```bash
sh scripts/setup_unix.sh
sh scripts/run.sh
```

Открыть `http://localhost:1639`.

### Docker

```bash
docker compose up --build
```

Контейнер поднимается на `http://localhost:1639` (порт 8000 внутри). Тестовый набор
`Исследования_тест` подключается read-only и показывается на сайте; обучающие данные
в контейнер не монтируются. По умолчанию в Docker используется калибровочная модель
качества (`models/calibration_resnet18.pt`, см. `docker-compose.yml`).

### Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `DXA_DATA_ROOT` | Корень данных веб-интерфейса | `./Исследования_тест` |
| `DXA_LABELS_PATH` | Путь к разметке | `./annotations/labels.csv` |
| `DXA_MODEL_PATH` | Основная модель контроля качества | `./models/dxa_qc_resnet18.pt` |
| `DXA_CALIBRATION_PATH` | Калибровочная модель | `./models/calibration_resnet18.pt` |
| `DXA_PREVIEW_ROOT` | Каталог временных предпросмотров | `<temp>/dxa-qc-previews` |

Готовая модель уже находится в `models/dxa_qc_resnet18.pt`, поэтому для обычной
проверки снимков переобучение не требуется.

## Веб-интерфейс

На главном экране можно перетащить до 50 файлов DICOM, JPEG, PNG или WebP размером
до 25 МБ каждый и получить отдельный результат для каждого снимка: область, сторону,
итоговое решение (хороший/плохой), нарушенные критерии и статус решения. Загруженные
файлы не сохраняются.

На предпросмотр накладывается ориентировочная геометрическая разметка: расчетная ось,
угол и контрольные уровни для позвоночника либо ось и ROI для бедра. Это объясняющая
визуализация, а не экспертная сегментация.

Разметка (экспертные метки) ведётся в `annotations/labels.csv`; просмотр и правка
доступны через API (`GET /api/annotations`, `PUT /api/annotations/{image_uid}`).

Интерактивная документация API доступна в Swagger UI: `http://localhost:1639/docs`.

## Разметка (annotations/labels.csv)

Разделитель `;`, схема (значение 1 в колонке критерия = критерий нарушен):

```
path_to_study;study_uid;image_uid;anatomical_region;side;quality_class;
correct_positioning;spine_axis_alignment;foreign_objects_artifacts;
hip_positioning_rotation;hip_roi_correctness;notes;exclude_from_training
```

- `anatomical_region`: `lumbar_spine` / `hip` (синоним `proximal_femur`) — при чтении
  канонизируется в `proximal_femur`;
- `side`: `none` для позвоночника, `right`/`left` для бедра;
- `quality_class` согласовывается с критериями: 1 ⇔ нарушен хотя бы один критерий;
  пустой `quality_class` = строка ещё не размечена (в обучение не идёт).
  Значения `quality_class` в обучении НЕ используются как цель: итоговое качество
  модель выводит из критериев (`derived_quality` в `scripts/train_model_2.py`);
- `exclude_from_training=True` исключает изображение из обучения без удаления файлов
  (журнал исключений — `excluded_images/manifest.csv`, инструмент
  `scripts/exclude_images.py`);
- `path_to_study` можно записывать упрощённо (`1\1_1\п.dcm`) — при обучении файл
  ищется по имени внутри папки исследования.

## Обучение и оценка

```bash
PYTHONPATH=src .venv/Scripts/python.exe scripts/train_model_2.py   # обучение
PYTHONPATH=src .venv/Scripts/python.exe scripts/evaluate_model.py  # метрики на test
PYTHONPATH=src .venv/Scripts/python.exe scripts/batch_inference.py # CSV-отчёт по Results
```

Повторное обучение на Windows (PowerShell):

```powershell
.\scripts\train_windows.ps1 -Epochs 15
```

- Разделение train/validation — 85/15 **по study_uid**: изображения одного
  исследования никогда не попадают в разные сплиты (нет утечки). Тестовые снимки
  из Results не выделяются: тестирование модели — на внешней папке
  `Исследования_тест` (вручную через интерфейс или `scripts/batch_inference.py`).
- Итоговое качество не обучается по колонке `quality_class`: плохой снимок =
  нарушен хотя бы один применимый критерий (цель собирается из критериев).
- Критерии чужой области исключаются из loss маской (masked violation loss).
- Дисбаланс классов учтён весами (region/side/quality/criteria) и метриками с support.
- Пороги, ранняя остановка и метрики — по validation; оценка метрик оптимистична,
  т.к. эта же выборка участвует в подборе порогов (`models/metrics.json`,
  bootstrap-CI для качества).
- Ранняя остановка: обучение прекращается, если composite-скор validation не растёт
  4 эпохи подряд.

Готовые веса находятся в `models/dxa_qc_resnet18.pt`, метрики — в
`models/metrics.json`, фиксированное разбиение — в `models/splits.csv`.
Калибровочная модель (по методичке, с клинической головой) хранится отдельно:
`models/calibration_resnet18.pt`, модуль `dxa_qc/calibration.py`.

Модель: ResNet18 с отдельными головами для анатомической области, стороны, бинарного
качества и пяти экспертных критериев.

## Тесты

```bash
PYTHONPATH=src .venv/Scripts/python.exe -m pytest   # Windows
PYTHONPATH=src .venv/bin/python -m pytest           # macOS/Linux
```

Тесты (`tests/`) покрывают API, геометрию, инференц (включая ось), ML-утилиты,
резервные правила QC, репозиторий разметки и обучающий конвейер. Настройки pytest —
в `pyproject.toml` (`pythonpath=src`, `testpaths=tests`).

## Ограничения

Модель обучена на исследовательской разметке 80 исследований (207 снимков). Метрики
считаются на validation и отражают только этот набор; клиническую точность они не
доказывают. Support нескольких критериев очень мал (единицы изображений), поэтому
per-class F1 по ним не показателен — см. `support` и `unsupported_in_split`
в `models/metrics.json`. Финальная проверка — на внешней папке `Исследования_тест`.
Оценка ротации и артефактов требует проверки профильным специалистом.
